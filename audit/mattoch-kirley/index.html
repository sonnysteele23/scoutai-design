The five findings that matter

01

No robots.txt (HTTP 404).

Not fatal, but Google has no sitemap pointer and the sitemap is only discoverable by guessing /sitemap.xml.

02

Insecure redirect hop: https://www.mattochkirley.com/ -> 301 -> http://mattochkirley.com/ -> 301 -> https://mattochkirley.com:443/.

Anyone typing 'www' is bounced through plain HTTP; browsers may show a warning and the :443 in the Location header is sloppy.

03

No Open Graph or Twitter Card tags at all (og: {} / twitter: {}).

Shared links show no image, no description - for a firm that relies on referrals being passed around, that is a visible credibility hit.

04

No first-party analytics: no GA4, GTM or Meta pixel.

The only tracker is searchatlas.com/api/track/v1.js, so the data lives with the vendor. The contact form posts to api.builder.searchatlas.com - if the vendor contract ends, the form and the site go with it.

05

Zero social links and a broken BBB seal (bbb.org/seals/blue-seal-293-61-whitetxt-bbb-1000133684.png -> 404).

The 'Trusted across the islands' section has nothing external to click.

These are measurements, not design opinions. Each one is something your current provider could have run in ten minutes.

What I would do in the first week

  • Add robots.txt with the sitemap line.
  • Fix the www redirect to go straight to https://mattochkirley.com/ (one 301) and add HSTS.
  • Add OG/Twitter meta with a 1200x630 firm image.
  • Install GA4 + GTM in the builder's head-code slot; add a Meta pixel (PI firms retarget heavily).
  • Fix the BBB seal URL; add LinkedIn/Facebook/Google Business Profile links in the footer.
