The five findings that matter

01

No meta description at all (`meta_description: None`).

Google writes its own snippet from random page text; for 'ductless AC Honolulu' searches the listing reads worse than competitors'.

02

Template leakage in social previews: `og:site_name` is 'Bricks blueprint' and `og:title` is 'Home - RMI Mechanical'.

Any shared link says 'Bricks blueprint' next to the company name.

03

The home page tells Google it is an Article, not a business: the JSON-LD @type list is Article / Person / WebSite / ImageObject - no HVACBusiness or LocalBusiness with the Rose St address, (808) 422-5454 or Mon-Fri 8-4 hours that are already printed in the footer.

04

No analytics: the free-estimate form on the home page is the whole funnel, and nothing records how many people start or submit it.

05

Mobile is slow: Lighthouse mobile performance 56, LCP 12.2 s (desktop 94 / 1.2 s).

The hero image (1673x855 lazy-loaded SVG placeholder then full image) is the likely culprit; a homeowner searching 'AC repair' on a phone waits 12 s for the first picture.

These are measurements, not design opinions. Each one is something your current provider could have run in ten minutes.

What I would do in the first week

  • Write a 150-char meta description and a real title ('Mitsubishi Ductless AC Installation Honolulu | RMI Mechanical').
  • Set the site name in Bricks/Yoast so og:site_name = 'RMI Mechanical'; switch home-page schema from Article to HVACBusiness with NAP, hours, licence.
  • Install GA4 + GTM; track estimate-form submissions and tel: taps.
  • Preload the hero image at a mobile size (fetchpriority=high, no lazy-load above the fold).
  • Add a Google Maps embed + GBP review link in the footer; enable HSTS.
