The five findings that matter

01

Name-Address-Phone mismatch with the BBB.

The BBB-listed number (808) 836-4548 appears nowhere on the home page or /contact/ (0 matches); the site publishes 808-833-1611 for Oahu and the clickable tel: link is (888) 717-6925. Google cross-checks phone numbers across BBB, Maps and the site; inconsistency erodes local-pack ranking and confuses callers.

02

Desktop layout jumps badly: Lighthouse desktop CLS 0.635 (threshold for 'good' is 0.1).

Content shifts under the cursor after load - a known cause of mis-clicks and a direct Core Web Vitals ranking penalty.

03

1.53 MB of HTML on the home page (vs.

~60-200 KB for the rest of this batch). NitroPack inlines everything; mobile LCP measured 4.6 s.

04

45 of 58 images have no alt attribute in the delivered HTML (data:image/svg placeholders from NitroPack).

Screen readers and Google Images see nothing; Lighthouse accessibility 81, best-practices 58.

05

robots.txt declares sitemaps for eight other domains (dewittguam.com, royalalaskanmovers.com, approvedforwarders.com, ...).

Google ignores cross-host sitemap declarations unless the host is verified in the same Search Console property, and it signals a copy-pasted template.

These are measurements, not design opinions. Each one is something your current provider could have run in ten minutes.

What I would do in the first week

  • Put (808) 836-4548 (or whichever number is canonical) on the site, the BBB profile and Google Business Profile - one number everywhere; make the header tel: an 808 number.
  • Reserve space for the elements that shift on desktop (hero slider / notification bar) to kill the 0.635 CLS.
  • Verify NitroPack's lazy-load preserves alt attributes; otherwise disable image lazy-loading for above-the-fold logos.
  • Add PostalAddress + openingHours to the existing Corporation schema; emit FAQPage schema on the FAQ pages (the avada_faq post type already exists).
  • Trim robots.txt to this domain's sitemap only.
