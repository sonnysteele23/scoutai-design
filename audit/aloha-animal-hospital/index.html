The five findings that matter

01

The home page is 24 MB: Lighthouse total page weight 24,020 KB, mobile LCP 15.3 s (performance 56), desktop CLS 0.771.

On a phone on cellular the hero takes a quarter of a minute and the desktop layout jumps after load. Almost certainly the hero video/images (uploads dated 2026/04) shipped uncompressed - a media fix, not a code fix, but today it undercuts everything else the site does right.

02

Pinch-zoom is disabled: `viewport: width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=0` (Lighthouse a11y 'meta-viewport' fail).

Older pet owners cannot enlarge text; WCAG 1.4.4 failure.

03

No online booking - 'Request an appointment' is a WPForms form that emails the clinic.

After-hours visitors (the urgent-care segment the site advertises) get no confirmed slot.

04

No Meta pixel or Google Ads tag, so no retargeting of the people who viewed Urgent Care or Surgery pages; only GA4/GTM measurement.

05

Small misses on an otherwise complete setup: /llms.txt returns 200 with the HTML home page (soft-404); the home-page JSON-LD includes an 'Article' type alongside LocalBusiness; the FAQs page has no FAQPage schema.

These are measurements, not design opinions. Each one is something your current provider could have run in ten minutes.

What I would do in the first week

  • Compress/resize the hero media (target < 3 MB total page weight; poster image + lazy video) and reserve its box to stop the desktop CLS.
  • Remove user-scalable=0 / maximum-scale=1.0 from the Divi viewport setting.
  • Add FAQPage schema to /faqs and drop the Article type from the home page.
  • Add Meta pixel via the existing GTM container; build an Urgent Care / Surgery audience.
  • Return a real llms.txt (or 404).
  • Pilot an online booking widget (PetDesk/Vetstoria) in the hero.
